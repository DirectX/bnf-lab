# BNF-лаборатория

Одностраничное учебное приложение к **Теме 4, практическому занятию 1**:
грамматика мини-языка записывается в БНФ и тут же проверяется — и сама,
и лексером на примерах программ.

> Главное, что должен унести студент: **приоритет операций задаётся
> структурой правил, а не отдельным механизмом.**

## Запуск

```bash
npm install
npm run dev        # разработка, http://localhost:5173
npm run build      # статический билд в dist/ (можно раздавать с любого сервера / file-совместимо по base './')
npm run preview    # прод-превью собранного
npm test           # смоук-тесты ядра (грамматика + лексер) на Node
```

Интернет нужен только для `npm install`. Билд полностью статический.

## Что уже работает (часть 1)

**Редактор БНФ** — с подсветкой и живой проверкой грамматики:

- синтаксис: `<нетерминал> ::= альт | альт`, литералы `"в кавычках"`,
  классы лексем `ПРОПИСНЫМИ` (`ИДЕНТ`, `ЧИСЛО`), группы `(а|б)`,
  `[необязательно]`, модификаторы `*` `+` `?`, пустота `ε`, комментарии `#`;
- диагностика с переходом по клику на строку: ошибки синтаксиса,
  ссылка на неопределённое правило, недостижимые правила;
- учебные подсказки: **левая рекурсия** (прямая и через цепочку — с отсылкой,
  что в занятии 2 её придётся превращать в цикл, а bison из занятия 3 примет как есть),
  **эвристики неоднозначности**: «одна альтернатива — начало другой» и
  «вложенная конструкция с необязательным хвостом» — обе схемы висячего else;
- из грамматики автоматически извлекается словарь лексера: таблица ключевых
  слов, знаки операций, используемые классы.

**Лексер мини-языка** — с позиции занятия 1:

- максимальное совпадение: `<=` — одна лексема, `while1` — идентификатор
  (ключевое слово проверяется по таблице после чтения слова целиком);
- у каждой лексемы строка и столбец — «без этого парсер не скажет, где ошибка»;
- переключатель «строгие числа»: `12abc` — ошибка или два токена,
  решение принимает студент, но оно должно быть записано и покрыто тестом;
- замечание про восьмибитную ячейку (`256` не влезет в тип языка);
- переключатель комментариев `//` и `/* */` — отсылка к домашнему заданию;
- границы модуля соблюдены: лексер **не знает про грамматику** —
  `) ) + = while` для него корректный вход (тест есть);
- сравнение лексем с правилами: если токен не встречается ни в одном
  правиле — приложение честно об этом предупредит.

**Тестовые строки** — чипами: корректные, пограничные (`12abc`, `while1`,
`<=` против `<`) и негативные, как в блок-5 занятия.

## Структура

```
src/
  grammar/parser.js   — разбор БНФ-текста в AST с позициями и recover-ошибками
  grammar/analyze.js  — desugar модификаторов, достижимость, левая рекурсия,
                        эвристики неоднозначности, извлечение словаря
  lexer/lexer.js      — лексер мини-языка (максимальное совпадение, позиции)
  ui/editor.js        — редактор: прозрачная textarea поверх подсвеченного pre
  ui/highlighters.js  — подсветка БНФ и программы (по токенам лексера)
  data/presets.js     — пресеты грамматик и тестовые строки занятия
scripts/smoke.mjs     — смоук-тесты ядра без браузера
```

## Дорожная карта (занятия 2 и 3)

Вкладки «Парсер и AST» и «Bison и конфликты» — заглушки-роадмапы,
написанные по методическим указаниям занятий 2 и 3.

* **Занятие 2:** парсер-рекурсивный спуск прямо из грамматики (правило →
  функция, левая рекурсия → цикл), визуализация AST («умножение глубже
  сложения»), генерация мнемоник для эмулятора студента (`LDA/ADD/STA`,
  `PUSH/POP`, адрес вперёд с обратной правкой), запуск и эталонные тесты.
* **Занятие 3:** экспорт грамматики в `.y`, компиляция через bison
  **на отдельном Node-бэкенде** (фронтенд остаётся статическим —
  yacc-утилитам там место), живой конфликт сдвиг/свёртка на висячем else,
  бланк замера «рукописный против генератора».
