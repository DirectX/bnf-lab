# BNF-лаборатория

Одностраничное учебное приложение к **Теме 4, практическому занятию 1**:
грамматика мини-языка записывается в БНФ и тут же проверяется — и сама,
и лексером на примерах программ.

> Главное, что должен унести студент: **приоритет операций задаётся
> структурой правил, а не отдельным механизмом.**

## Запуск

```bash
npm install
npm run dev        # разработка, http://localhost:5173
npm run build      # статический билд в dist/ (можно раздавать с любого сервера / file-совместимо по base './')
npm run preview    # прод-превью собранного
npm test           # смоук-тесты ядра (грамматика + лексер) на Node
npm run crosscheck # сверка SLR(1) приложения с живыми bison и jison
```

Интернет нужен только для `npm install`. Билд полностью статический.

## Что уже работает

### Часть 1 — редактор БНФ + лексер (занятие 1)

**Редактор БНФ** — с подсветкой и живой проверкой грамматики:

- синтаксис: `<нетерминал> ::= альт | альт`, литералы `"в кавычках"`,
  классы лексем `ПРОПИСНЫМИ` (`ИДЕНТ`, `ЧИСЛО`), группы `(а|б)`,
  `[необязательно]`, модификаторы `*` `+` `?`, пустота `ε`, комментарии `#`;
- диагностика с переходом по клику на строку: ошибки синтаксиса,
  ссылка на неопределённое правило, недостижимые правила;
- учебные подсказки: **левая рекурсия** (прямая и через цепочку — с отсылкой,
  что в занятии 2 её придётся превращать в цикл, а bison из занятия 3 примет как есть),
  **эвристики неоднозначности**: «одна альтернатива — начало другой» и
  «вложенная конструкция с необязательным хвостом» — обе схемы висячего else;
- из грамматики автоматически извлекается словарь лексера: таблица ключевых
  слов, знаки операций, используемые классы.

**Лексер мини-языка** — с позиции занятия 1:

- максимальное совпадение: `<=` — одна лексема, `while1` — идентификатор
  (ключевое слово проверяется по таблице после чтения слова целиком);
- у каждой лексемы строка и столбец — «без этого парсер не скажет, где ошибка»;
- переключатель «строгие числа»: `12abc` — ошибка или два токена,
  решение принимает студент, но оно должно быть записано и покрыто тестом;
- замечание про восьмибитную ячейку (`256` не влезет в тип языка);
- переключатель комментариев `//` и `/* */` — отсылка к домашнему заданию;
- границы модуля соблюдены: лексер **не знает про грамматику** —
  `) ) + = while` для него корректный вход (тест есть);
- сравнение лексем с правилами: если токен не встречается ни в одном
  правиле — приложение честно об этом предупредит.

**Тестовые строки** — чипами: корректные, пограничные (`12abc`, `while1`,
`<=` против `<`) и негативные, как в блок-5 занятия.

### Часть 2 — парсер и AST (занятие 2)

Парсер строится **прямо по БНФ со страницы** — обещание «грамматика
превращается в код механически» работает буквально:

- **правило → функция**: псевдокод `разобрать_<X>()` для каждого нетерминала,
  как на доске в блоке 1; **прямая левая рекурсия показана уже превращённой
  в цикл** «пока…» (правила-превращения подсвечены);
- распознаватель с откатом и мемоизацией по раскрытой грамматике;
  недостижимые косвенные левые рекурсии не вызывают зависания;
- **ошибки с позицией** в стиле «ожидать токен, иначе ошибка»: разбор
  сообщает, до какой лексемы дошёл, какого числа строки и столбца, и чего
  ожидал — тот самый «пять минут сейчас экономят час потом»;
- **AST**: дерево с правилами-узлами; клик по узлу подсвечивает покрытые
  лексемы, клик по лексеме — выделяет ближайший узел; крупные поддеревья
  сворачиваются; проверка «умножение глубже сложения» глазами;
- **трасса применения правил** — порядок, в котором функции вызывались:
  «дерево строится по правилам, на каждом шаге называется применяемое
  правило» (блок 3 занятия 1 — теперь не на бумаге);
- при неоднозначной грамматике — честная плашка «показан один из возможных
  разборов»; рукописный парсер решает неоднозначность молча.

**Генератор → TinyCPU-8** (та же вкладка, низ страницы):

- AST компилируется в машинный код целевой машины — порт эталонного
  `tinycpu.py` встроен (`src/cpu8/`), тесты — порт `check.py`;
- листинг генерируется **в формате ассемблера tinycpu-web** (метки, `DB`,
  комментарии): кнопка «Копировать листинг» → вставка на
  [directx.github.io/tinycpu-web](https://directx.github.io/tinycpu-web/) —
  программа собирается и идёт один в один;
- кнопки «Запустить» прямо в браузере: видно A/PC/SP, число шагов и какие
  значения легли в ячейки переменных (до/после, изменения подсвечены);
- учебные сюжеты в листинге с комментариями: **PUSH/POP** при одном
  аккумуляторе, **константы в памяти** (ADD не умеет immediate),
  **умножение циклом сложений** (в машине нет MUL), **a <= b перебором вниз**
  (нет флага «меньше»), **адрес вперёд двумя проходами** — обратная правка;
- деление и константы > 255 — отказ с объяснением; «12abc» и «y = 256»
  добавлены в тестовые чипы как негативные.

### Часть 3 — снизу вверх: SLR(1), конфликты, экспорт в .y (занятие 3)

Приложение строит LR-таблицы само — тот же алгоритм, что внутри bison,
только видимый изнутри, без сервера и без внешнего инструмента:

- **конфликты как свойство языка**: состояние автомата, пункт `A → α · β`,
  lookahead — и два хода на нём. Для пресета «висячий else» — ровно один
  shift/reduce на `"else"`, как у настоящего bison;
- **политика разрешения** (сдвиг/свёртка) — с учебным открытием: слепая
  галка «свёртка» закрывает *оба* вложенных if и программа перестаёт
  приниматься. Конфликт так не выключают: разрешение — это `%prec`
  (способ первый, практичный) или переписывание грамматики на
  `<согласованный>`/`<несогласованный>` (способ второй, честный —
  пресет «Висячий else — переписан» даёт 0 конфликтов);
- **трасса ходов снизу вверх**: стек состояний, сдвиги, свёртки, момент
  конфликта — рядом с рукописным спуском части 2;
- **таблица сравнения** «рукописный против генератора» по живой программе:
  левая рекурсия (цикл vs напрямую), неоднозначность (молчаливый выбор vs
  явное объявление), диагностика;
- **экспорт в `.y`**: раскрытая грамматика в синтаксисе bison (обычный BNF —
  bison 3.8 не понимает EBNF), транслитерация имён, `%expect` с числом
  конфликтов, которые приложение нашло само;
- **бланк замера** (блоки 4–5): строки, время реализации, **время внесения
  изменения**, число затронутых мест — с автоформулировкой вывода по
  заполненным цифрам; сохраняется в localStorage.

## Проверено живыми инструментами

`npm run crosscheck` — собственный SLR(1)-движок сверяется с
**GNU Bison 3.8** и **jison** на всех четырёх пресетах:
`mini` 1=1=1, `ambig` 4=4=4, `dangling` 1=1=1, `dangling_fixed` 0=0=0.
Экспортированный `.y` компилируется bison без ошибок, `%expect` подтверждён.

## Дорожная карта

* **Занятие 3 в классе:** `bison -d mini.y` по экспорту из приложения,
  чтение `.output`-отчёта, разрешение конфликта `%prec` vs переписывание,
  заполнение бланка замера всей группой и сведение цифр.
* **Свои грамматики:** приложение компилирует мини-язык занятия 1; студент
  со своей грамматикой получает разбор/AST/SLR, но генератор кода — только
  для покрытых конструкций (честный отказ с указанием узла).

## Архитектура приложения (для преподавателя)

Вкладки deep-link'ятся: `#tab1`, `#tab2`, `#tab3` — можно давать ссылку
на конкретную часть прямо на занятии.

## Структура

```
src/
  grammar/parser.js    — разбор БНФ-текста в AST с позициями и recover-ошибками
  grammar/analyze.js   — desugar модификаторов, достижимость, левая рекурсия,
                         эвристики неоднозначности, извлечение словаря
  lexer/lexer.js       — лексер мини-языка (максимальное совпадение, позиции)
  parser/rd.js         — рекурсивный спуск по раскрытой грамматике: откат,
                         мемоизация, левая рекурсия → цикл, ошибки с позицией
  parser/pseudocode.js — псевдокод «правило → функция» для вкладки 2
  cpu8/cpu8.js         — эмулятор TinyCPU-8 (порт эталонного tinycpu.py)
  cpu8/codegen.js      — AST → машинный код + листинг для ассемблера tinycpu-web
  lr/slr.js            — построение SLR(1): пункты, состояния, FIRST/FOLLOW,
                         таблицы ACTION/GOTO, конфликты с примером входа
  lr/run.js            — прогон по таблице снизу вверх: трасса ходов, AST,
                         политика разрешения конфликта
  lr/exporty.js        — экспорт раскрытой грамматики в .y для bison
  ui/editor.js         — редактор: прозрачная textarea поверх подсвеченного pre
  ui/highlighters.js   — подсветка БНФ и программы (по токенам лексера)
  data/presets.js      — пресеты грамматик и тестовые строки занятия
scripts/smoke.mjs      — смоук-тесты ядра без браузера (npm test)
scripts/crosscheck.mjs — сверка с живыми bison/jison (npm run crosscheck)
reference/tinycpu.py   — эталонная машина (исходный Python, не исполняется в вебе)
reference/check.py     — эталонные тесты: python3 reference/check.py (11/11 — порт честный)
```

Машина-цель: **TinyCPU-8** — 256 байт памяти, аккумулятор, 12 команд,
операнд — байт-адрес. JS-исполнение листингов —
[tinycpu-web](https://directx.github.io/tinycpu-web/)
([репозиторий](https://github.com/DirectX/tinycpu-web/)).
