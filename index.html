Часть 2. Парсер методом рекурсивного спуска и генератор кода

в разработке

По методическим указаниям к занятию 2: довести конвейер до конца — программа на мини-языке компилируется и выполняется на собственном эмуляторе студента. Здесь сходятся Тема 1 (машина), Тема 2 (декомпозиция) и Тема 4.

Правило → функция. Соответствие механическое: <выражение> ::= <слагаемое> | <выражение> "+" <слагаемое> превращается в разобрать_выражение() почти построчно.
Левая рекурсия → цикл. Анализатор из части 1 уже подсвечивает левую рекурсию — в парсере она станет циклом, дающим левую ассоциативность.
Живой AST. Дерево для x = 2 + 3 * (4 - 1): умножение глубже сложения, скобок в дереве нет — они уже сделали своё дело.
Генератор кода. Обход в постфиксном порядке → LDA / ADD / STA; PUSH/POP для вложенных выражений; адрес вперёд с обратной правкой для if и while.
Таблица имён и запуск. Переменные — в области данных, не пересекающейся с кодом; мнемоники рядом с байтами; эталонные тесты — 5–6 штук одним запуском.

Часть 3. Рукописный парсер против генератора. Конфликты и стоимость изменения

в планах

По методическим указаниям к занятию 3: основание для инженерного выбора — не чужое мнение, а собственный замер. И конфликт сдвиг/свёртка перестаёт быть словами с лекции.

Экспорт в .y.Grammatика из части 1 перегенерируется в файл bison — левая рекурсия записывается напрямую, без переписывания в цикл.
Node-бэкенд. Компиляция .y через bison — на отдельном сервере: фронтенд остаётся статическим, yacc-утилиты живут там, где им место.
Конфликт сдвиг/свёртка вживую. Тот же «висячий else», который анализатор части 1 уже помечает, bison покажет как реальный конфликт — с разбором сообщения.
Бланк замера. Строк кода, время реализации, время внесения изменения в язык, число затронутых мест — в рукописном и bison-вариантах.
Вывод. Малый и стабильный язык — рукописный спуск дешевле; большой и меняющийся — генератор окупается.

Учебный конвейер: текст → лексер → токены → парсер → AST → байты → эмулятор. Сейчас работает первая ступень — лексер не знает про грамматику и проверяет только форму лексем: «) ) + = while» для него корректный вход.
